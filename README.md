# 🛣️ ИС планирования и контроля процессов нанесения дорожной разметки

Мой дипломный проект: ERP-система (lite) для управления заявками и учета дорожных работ.

## О проекте

Система разрабатывалась с оглядкой на реальные бизнес-процессы (в частности, работу с аппаратно-программными комплексами КСАР, которые используются на технике компании СТиМ).

Основная идея в том, чтобы уйти от ручного ввода выполненных объемов. Вместо этого диспетчер загружает в систему XML-файл (лог КСАР), выгруженный с бортового компьютера разметочной машины. Система парсит этот лог, вытягивает GPS-координаты, рисует фактический трек на карте и автоматически высчитывает расход материалов (краски и стеклошариков) для бухгалтерии согласно нормам.

### Разделение ролей

В приложении реализовано два изолированных рабочих места:

1. **Диспетчер (Админ-панель):** Доступ к дашбордам, drag&drop календарю планирования, загрузке XML-проектов, карте всех объектов и генерации складских отчетов.
2. **Бригадир (Мобильный АРМ):** Упрощенный интерфейс для телефона. Человек на трассе видит только назначенные на него объекты, может взять их в работу и открыть маршрут на карте. Никаких лишних таблиц и чужих данных.

## 🛠️ Стек технологий

* **Backend:** C#, ASP.NET Core 8, Blazor Server
* **База данных:** PostgreSQL + Entity Framework Core (Code-First)
* **Карты (ГИС):** JS interop + Leaflet.js
* **Парсинг:** LINQ to XML
* **Авторизация:** Cookie-based Auth (Role-based Access Control)

## ⚙️ Как запустить локально

1. Склонируйте репозиторий и перейдите в папку проекта:

   ```bash
   git clone <URL_репозитория>
   cd KsarErpLite
   ```

2. Настройте подключение к БД. Откройте `appsettings.json` и пропишите свои данные для PostgreSQL:

   ```JSON
   "ConnectionStrings": {
     "DefaultConnection": "Host=localhost;Database=KsarErpDb;Username=postgres;Password=ВашПароль"
   }
   
   ```

3. Накатите миграции, чтобы Entity Framework создал таблицы:

   ```Bash
   dotnet ef database update
   ```

4. Запустите проект:

   ```Bash
   dotnet run
   ```

## 🔐 Тестовые данные для входа

По умолчанию база создается пустой. Чтобы протестировать роли, выполните SQL-запрос в вашей СУБД для создания первого диспетчера:

```SQL
INSERT INTO "Users" ("Id", "FullName", "Login", "PasswordHash", "Role") 
VALUES (gen_random_uuid(), 'Диспетчер', 'admin', '123', 0);
```

После входа под логином `admin` (пароль `123`) вы сможете создавать учетные записи бригадиров прямо через интерфейс (раздел "Пользователи").
